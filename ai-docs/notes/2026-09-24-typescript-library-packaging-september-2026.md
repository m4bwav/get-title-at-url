# TypeScript library packaging for maximum reach, September 2026

Research for rewriting get-title-at-url as a ~60-line TypeScript URL-title fetcher (fetch, `<title>`/og:title) with a small Node CLI, published so it works from ESM and CommonJS with types, on Node, Bun, Deno, browsers and edge runtimes. Every fact was verified on 2026-09-24/25 against the source named; nothing is from memory. UNVERIFIED marks what could not be confirmed. Empirical checks ran in the session scratchpad on Node v24.18.0 / npm 11.16.0 (Windows 11); the demo project is described at the end.

## Summary

- Build with tsdown 0.23.0 (tsup is unmaintained and its README points to tsdown); the two-entry config in section 1 emits index.mjs, index.cjs, index.d.mts, index.d.cts and cli.mjs with the shebang kept, and passed publint and attw (the arethetypeswrong CLI).
- TypeScript 7.0.2 (Go compiler) is current; 6.0 changed the defaults (strict, esnext, es2025, empty types). Use module nodenext with verbatimModuleSyntax, erasableSyntaxOnly and rewriteRelativeImportExtensions; the tsconfig/node22 and tsconfig/node-ts bases give exactly that.
- Node type stripping is on by default in 22.18+ and 24 (stable from 24.12); node --test runs .test.ts files directly there; Node 20 (EOL 2026-04-30) cannot.
- require(esm) is unflagged in Node 20.19+, 22.12+, 23+ and 24; Node's guide, Anthony Fu, Sindre Sorhus and Joyee Cheung all favour ESM-only, but dual costs a few config lines and adds reach on older Node and tooling, so the plan can pick dual.
- JSR holds about 22,100 packages; the same TypeScript source can publish through jsr.json and npx jsr publish with OIDC; ESM only, explicit return types; optional after npm.
- fetch, AbortSignal.timeout, URL.canParse and legacy TextDecoder labels exist on Node 20/22/24 (full-icu), Deno, Bun 1.2.21+, Workers (compatibility date 2022-10-31 or later) and browsers since 2023; wrap TextDecoder in try/catch.
- cheerio costs 21 packages and about 8.7 MB, and article-title does not read og:title; no maintained zero-dependency title extractor exists, so write one (entities is the only useful zero-dependency piece).
- Lint: xo 5.0.1 (flat config, TypeScript built in, Prettier bundled, Node 22+) for continuity, Biome 2.5.14 for one fast binary.

Note on spelling: npm scope names are written here without their leading at-sign (the repository doc lint reads them as personal handles); restore it when installing, for example the arethetypeswrong CLI package or the biomejs/biome package.

## 1. Build tool: tsdown vs tsup vs tsc

- tsdown 0.23.0 is the latest (npm 2026-09-03; GitHub release 2026-09-03T17:35Z). Still 0.x, no 1.0. 3.43M downloads/week vs tsup 6.20M (api.npmjs.org, week to 2026-09-21). (https://api.github.com/repos/rolldown/tsdown/releases; `npm view tsdown`, 2026-09-25)
- tsdown is "an official project of Rolldown" (Rust bundler). Its docs say it "was heavily inspired by tsup, and even incorporates parts of its codebase"; it does not call itself tsup's successor. tsup's README does: "This project is not actively maintained anymore. Please consider using tsdown instead." tsup latest 8.5.1, 2025-11-12. (https://tsdown.dev/guide/ and https://tsdown.dev/guide/migrate-from-tsup, fetched 2026-09-24; https://github.com/egoist/tsup, fetched 2026-09-24; npm)
- Defaults vs tsup: format esm (tsup cjs); clean true; dts auto-on when package.json has types/typings/exports.types or tsconfig has declaration:true; target read from engines.node. `npx tsdown-migrate` converts a tsup setup. (migrate page; https://tsdown.dev/options/dts)
- Dev-time engines: node ^22.18.0 || ^24.11.0 || >=26.0.0; peer typescript ^5 || ^6 || ^7 (npm, 2026-09-25). This does not constrain the consumer floor.
- platform: `node` (default) | `neutral` ("no specific runtime assumptions", resolves only through `exports`) | `browser`; "For the CJS format, the platform is always set to 'node' and cannot be changed." (https://tsdown.dev/options/platform, 2026-09-24)
- fixedExtension: "The extension will always be .cjs or .mjs. Otherwise, it will depend on the package type"; default true only when platform is node. unbundle: output mirrors the source tree per file, default false, pointless for two files. exports: true writes `exports` plus legacy main/module/types; its `bin` mode "Scans entry chunks for shebangs (e.g. #!/usr/bin/env node). If exactly one is found, it is used as the bin entry"; docs: review the result "or enable publint for validation". `publint: true` and `attw: true` run those tools after each build. (https://tsdown.dev/reference/api/Interface.UserConfig; https://tsdown.dev/reference/api/Interface.ExportsOptions; https://tsdown.dev/options/unbundle; https://tsdown.dev/options/package-exports; https://tsdown.dev/reference/cli, all 2026-09-24)
- Shebang: the `#!/usr/bin/env node` line in src/cli.ts came through verbatim as line 1 of dist/cli.mjs, and tsdown logged "Granting execute permission to dist\cli.mjs" (tsdown 0.23.0 / rolldown 1.2.11, observed 2026-09-25). Rolldown's documented fallback is a per-chunk `banner`. (https://rolldown.rs/reference/Interface.OutputOptions)
- Plain tsc dual emit: the handbook warns that any solution emitting two module formats "while only type checking once leaves (at least) one of the outputs unchecked"; it means two tsconfigs, two builds and renames to .cjs/.d.cts. A bundler is simpler. (https://www.typescriptlang.org/docs/handbook/modules/guides/choosing-compiler-options.html, 2026-09-24)
- Verified config. Built with tsdown 0.23.0 + typescript 7.0.2; `npx publint` printed "All good!"; `attw --pack .` (the arethetypeswrong CLI) printed "No problems found" with node10, node16 (from CJS), node16 (from ESM) and bundler all green; `require('./dist/index.cjs')` and `import './dist/index.mjs'` both exposed `getTitleAtUrl`; `node dist/cli.mjs https://example.com` printed "Example Domain" (2026-09-25):

```ts
// tsdown.config.ts
import { defineConfig } from 'tsdown'

export default defineConfig([
  { entry: { index: 'src/index.ts' }, format: ['esm', 'cjs'], platform: 'neutral', dts: true, fixedExtension: true, exports: true },
  { entry: { cli: 'src/cli.ts' }, format: 'esm', platform: 'node', dts: false, fixedExtension: true },
])
```

Emits dist/index.mjs, `index.cjs`, `index.d.mts`, `index.d.cts`, `cli.mjs`. `exports: true` on the library config wrote into package.json:

```json
"main": "./dist/index.cjs",
"module": "./dist/index.mjs",
"types": "./dist/index.d.cts",
"exports": { ".": { "import": "./dist/index.mjs", "require": "./dist/index.cjs" }, "./package.json": "./package.json" }
```

Hand-written fields: `"type": "module"`, `"bin": { "get-title-at-url": "./dist/cli.mjs" }`, `"files": ["dist"]`, `"sideEffects": false` (publint suggests it), `"engines": { "node": ">=20.19.0" }` (tsdown then targets node20.19.0). Types resolve by sibling name (index.cjs to index.d.cts), so nested `types` conditions are unnecessary. Pitfall found: `exports: true` on the CLI config also adds a `"./cli"` subpath, which attw flags (no types, CJSResolvesToESM); keep the CLI as `bin` only. If exports are written by hand, the attw- and publint-approved shape is `{"import": {"types": "./dist/index.d.mts", "default": "./dist/index.mjs"}, "require": {"types": "./dist/index.d.cts", "default": "./dist/index.cjs"}}`.
- With typescript 7.0.2 tsdown emitted the declarations but warned "TypeScript 7.0 does not yet have a stable API and is experimental. Some options will be unavailable"; it also warns "We recommend using the ESM format instead of CommonJS" whenever cjs is requested (observed 2026-09-25).

(https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/, 2026-07-08)
- TypeScript 6.0 (2026-03-23) was "the last release based on the current JavaScript codebase" and changed defaults: strict true, module esnext, target es2025, types [] (list "node" explicitly), rootDir = tsconfig directory. `tsc --help` on 7.0.2 confirms target es2025, strict true, esModuleInterop true and module values node16, node18, node20, nodenext, preserve (observed). (https://devblogs.microsoft.com/typescript/announcing-typescript-6-0/)
- Library tsconfig per the handbook: `module: node18` or `nodenext`, `target` = lowest runtime, `strict`, `verbatimModuleSyntax`, `declaration`; `moduleResolution: bundler` is for app code. `erasableSyntaxOnly` (5.8) bans enum, namespaces with runtime code, parameter properties and `import =`/`export =`; "Combine --erasableSyntaxOnly with --verbatimModuleSyntax". `rewriteRelativeImportExtensions` (5.7) rewrites ./x.ts to ./x.js in emit, so source can use the `.ts` specifiers Node type stripping, Deno and JSR want. (handbook page above; https://www.typescriptlang.org/docs/handbook/release-notes/typescript-5-8.html; https://www.typescriptlang.org/tsconfig/)
- Bases (npm, all republished 2026-09-24; JSON from tsconfig/bases main): tsconfig/node20 20.1.10 = lib es2023, module nodenext, moduleResolution node16, target es2022, types [node], strict, esModuleInterop, skipLibCheck; tsconfig/node22 22.0.6 = same with lib es2024 + ESNext.Array/Collection/Iterator; tsconfig/node24 24.0.5 = target es2024; tsconfig/node-ts 23.6.4 = rewriteRelativeImportExtensions + erasableSyntaxOnly + verbatimModuleSyntax, meant to be stacked: `"extends": ["tsconfig/node22/tsconfig.json", "tsconfig/node-ts/tsconfig.json"]`. (https://raw.githubusercontent.com/tsconfig/bases/main/bases/node22.json etc. and README)
- Verified tsconfig (tsc 7.0.2 `--noEmit` clean on the demo): module and moduleResolution nodenext, target es2022, lib [es2024, dom], types [node], strict, verbatimModuleSyntax, isolatedModules, erasableSyntaxOnly, rewriteRelativeImportExtensions, declaration, noEmit (tsdown emits), skipLibCheck.
- Node type stripping: added v22.6.0 behind `--experimental-strip-types`; enabled by default v23.6.0 and v22.18.0; stable v25.2.0 and v24.12.0; `--experimental-transform-types` added v22.7.0, removed in v26. The v22 line docs (22.23.3) still say "Stability: 1.2 - Release candidate". No tsconfig is read, `.ts` in node_modules is not stripped, `import type` is required, enums/namespaces need the transform. (https://nodejs.org/api/typescript.html; https://nodejs.org/docs/latest-v22.x/api/typescript.html, 2026-09-24)
- Node 20 never had type stripping (feature starts at 22.6.0) and is EOL since 2026-04-30. (https://raw.githubusercontent.com/nodejs/Release/main/schedule.json)
- `node --test` runs `**/*.test.{cts,mts,ts}` and friends by default "Unless --no-strip-types is supplied" (v24.21.0 docs; the v22.23.3 docs say `--no-experimental-strip-types`), so Node 22.18+ and 24 need no loader. Confirmed on Node 24.18.0: `node --test` ran `sum.test.ts`, 1 pass. (https://nodejs.org/docs/latest-v24.x/api/test.html; https://nodejs.org/docs/latest-v22.x/api/test.html)

## 3. ESM-only vs dual; attw and publint

- require(esm) history: unflagged v23.0.0, v22.12.0, v20.19.0; experimental warning removed v23.5.0, v22.13.0, v20.19.0; "no longer experimental" v25.4.0; Node 24 inherits from 23. Detect with `process.features.require_module`; a required graph with top-level await throws ERR_REQUIRE_ASYNC_MODULE. (https://nodejs.org/api/modules.html#loading-ecmascript-modules-using-require, 2026-09-24)
- Older Node (18, 20.0-20.18, 22.0-22.11): `require()` of ESM throws ERR_REQUIRE_ESM, "An attempt was made to require() an ES Module" (marked deprecated in the v20.x docs). attw's wording for that consumer: they "will not be able to use this module without a dynamic import()". (https://raw.githubusercontent.com/nodejs/node/v20.x/doc/api/errors.md; https://github.com/arethetypeswrong/arethetypeswrong.github.io/blob/main/docs/problems/CJSResolvesToESM.md)
- Positions. Node's own guide: "It's generally best to publish only 1 format, either CJS or ESM. Not both" (dual-package hazard), noting CJS "can require() an ES Module without a flag as of 23.0.0 and 22.12.0" (https://nodejs.org/en/learn/modules/publishing-a-package, 2026-09-25). Anthony Fu, 2025-02-05: new packages ESM-only, "know your consumers" (https://antfu.me/posts/move-on-to-esm-only). Sindre Sorhus, gist updated 2026-09-23: "Since Node.js 22, you may be able to require() ESM modules. However, I strongly recommend moving to ESM instead." (https://gist.github.com/sindresorhus/a39789f98801d908bbc7ff3ecc99d99c). Joyee Cheung, 2025-12-30: ship ESM only with `"node": "^20.19.0 || >=22.12.0"` (https://joyeecheung.github.io/blog/2025/12/30/require-esm-in-node-js-from-experiment-to-stability/). tsdown prints the same advice.
- Trade-off. Dual costs about five config lines, a second artifact to test, the dual-package hazard (two module instances if both formats load; harmless for a stateless fetcher) and no top-level await in the CJS entry. It buys `require()` on Node 18, 20.0-20.18 and 22.0-22.11 (all EOL or superseded minors), older bundler/Jest setups, and attw's node10 column. With `engines >=20.19.0`, ESM-only already reaches every CJS consumer on a supported Node. Dual = maximum reach at trivial cost; ESM-only = ecosystem consensus.
- attw 0.18.5 (2026-07-09; node >=20): `attw --pack .` (the arethetypeswrong CLI, or its scoped package through npx --yes) (also `attw <tarball>`, `--from-npm`); profiles strict (default), node16, esm-only; `--ignore-rules`. Problems: NoResolution, UntypedResolution, FalseCJS "Masquerading as CJS" (CJS declaration, ESM JS), FalseESM "Masquerading as ESM" (fix: "Add a .d.cts file to represent the .cjs file"), CJSResolvesToESM "ESM (dynamic import only)", FallbackCondition, CJSOnlyExportsDefault, FalseExportDefault, MissingExportEquals, UnexpectedModuleSyntax, InternalResolutionError, NamedExports. Principle: "declaration files must represent exactly one JavaScript file ... cannot represent JavaScript files of two different module formats". attw judges resolution outcomes, not key order. (https://raw.githubusercontent.com/arethetypeswrong/arethetypeswrong.github.io/main/packages/cli/README.md; docs/problems/FalseCJS.md and FalseESM.md, 2026-09-24)
- publint 0.3.24 (2026-08-19; node >=18): `npx publint` (packs with `npm pack`; `--strict`, `--level`). Rules that matter here: EXPORTS_TYPES_SHOULD_BE_FIRST, EXPORTS_DEFAULT_SHOULD_BE_LAST, EXPORTS_MODULE_SHOULD_PRECEDE_REQUIRE, EXPORTS_TYPES_INVALID_FORMAT (.d.mts/.d.cts must match the JS format), FILE_INVALID_FORMAT, BIN_FILE_NOT_EXECUTABLE (bin file must start with a shebang), EXPORTS_VALUE_INVALID (values start with `./`), FILE_NOT_PUBLISHED, USE_TYPE, USE_FILES, USE_ENGINES_NODE, USE_SIDE_EFFECTS, USE_LICENSE. (https://publint.dev/rules; https://publint.dev/docs/cli, 2026-09-24)

## 4. JSR

- Size: the API reports 22,105 packages (https://api.jsr.io/packages?limit=1, 2026-09-25). PkgPulse's "40,000+ by early 2026" is secondary and contradicted by the API: UNVERIFIED. jsr.io says "JSR modules can be used in Node.js, Deno, Bun, Cloudflare Workers, and more." The `jsr` npm CLI is 0.14.3 (2026-02-12).
- Same TypeScript source as npm: "Both code written originally to use package.json, and code written originally for Deno can be published as a JSR package." Config is `jsr.json` (or deno.json): name `scope/pkg`, version, exports (`"./src/index.ts"` or `{".": ...}`), optional include/exclude. Every import must resolve at publish time (package.json deps, import maps, `npm:`/`jsr:` specifiers). "When a package.json is present in your package, modules may use 'sloppy imports'" (extensionless or `.js`-for-`.ts`); otherwise write ./greet.ts. (https://jsr.io/docs/publishing-packages; https://jsr.io/docs/package-configuration, 2026-09-24/25)
- Restrictions: ESM only ("You cannot publish CommonJS modules"; `.cjs`/`.cts` or `require()` is rejected); "All exported functions, classes, and variables must have explicit types" (explicit return types); `--allow-slow-types` publishes anyway at the cost of docs, types and consumer type-check speed; global type augmentation is banned. (https://jsr.io/docs/about-slow-types; https://jsr.io/docs/troubleshooting)
- CI: link the GitHub repository in the package's settings on jsr.io, then a job with `permissions: contents: read, `id-token` set to `write`` and `run: npx jsr publish` (OIDC, no secret). `jsr publish --dry-run` exists. (publishing-packages page)
- Consumers: `npx jsr add scope/pkg` or `bunx jsr add` writes `"npm:jsr/scope__pkg" (at-sign before jsr, plus a version range)` and `.npmrc` `jsr:registry=https://npm.jsr.io` (prefixed with an at-sign); JSR transpiles to JS plus .d.ts for node_modules users; pnpm 10.9+ and Yarn 4.9+ resolve `jsr:` natively. (https://jsr.io/docs/using-packages; https://jsr.io/docs/npm-compatibility)
- Verdict: cheap once the source already uses `.ts` specifiers and explicit return types (both wanted for Node type stripping anyway): one jsr.json plus one workflow job. Benefit is Deno users and generated docs; JSR ignores `bin`. Optional, after npm is solid.

## 5. Runtime portability

- Node: fetch unflagged v18.0.0, stable v21.0.0; AbortSignal.timeout v17.3.0 and v16.14.0; URL.canParse v19.9.0 and v18.17.0; TextDecoder global v11. Official binaries are full-icu ("The official binaries are also built in this mode"); full-ICU TextDecoder covers gbk, iso-8859-1/latin1 (mapped to windows-1252), windows-1252, shift_jis, euc-jp, big5; small-icu and no-ICU builds only utf-8/utf-16. All six labels decoded on Node 24.18.0 (ICU 78.3). Node 20/22/24 official builds: no gaps. (https://nodejs.org/api/globals.html; https://nodejs.org/api/url.html; https://nodejs.org/api/intl.html; https://raw.githubusercontent.com/nodejs/node/main/doc/api/util.md, 2026-09-24)
- Browsers (MDN browser-compat-data, main): AbortSignal.timeout Chrome 103 (complete 124), Firefox 100, Safari 16; URL.canParse Chrome 120, Firefox 115, Safari 17; the Encoding API labels gbk, shift_jis, euc-jp, big5, windows-1252 are mandatory for user agents. (https://raw.githubusercontent.com/mdn/browser-compat-data/main/api/AbortSignal.json and api/URL.json; https://developer.mozilla.org/en-US/docs/Web/API/Encoding_API/Encodings)
- Deno: fetch is a global; AbortSignal.timeout since 1.20, URL.canParse since 1.33 (BCD); TextDecoder resolves labels through encoding_rs `Encoding::for_label` with no allow-list (ext/web/lib.rs, main), and encoding_rs "implements the Encoding Standard fully" (docs.rs/encoding_rs 0.8.42); issue #31605 (2025-12-14, closed 2026-06-05) concerned only `stream: true` chunk boundaries for big5/shift_jis/euc-kr. (https://docs.deno.com/api/web/~/fetch; https://raw.githubusercontent.com/denoland/deno/main/ext/web/lib.rs; https://docs.rs/encoding_rs/latest/encoding_rs/; https://api.github.com/repos/denoland/deno/issues/31605)
- Bun: fetch, AbortController/AbortSignal, URL, TextDecoder are listed as implemented; AbortSignal.timeout 1.0.0, URL.canParse 1.0.2 (BCD). Legacy encodings arrived with PR #21835 "Add WebKit text codec support for 24 additional encodings" (GBK, GB18030, Big5, EUC-JP, EUC-KR, ISO-2022-JP, Shift_JIS plus 11 single-byte), merged 2025-08-15, released in Bun 1.2.21 (2025-08-25) per the team's close of issue #10696. Gap: Bun below 1.2.21 throws on 'gbk'. (https://bun.com/docs/runtime/web-apis; https://api.github.com/repos/oven-sh/bun/pulls/21835; https://api.github.com/repos/oven-sh/bun/issues/10696/comments)
- Cloudflare Workers: fetch in the request context; AbortSignal.timeout since 2021-12-10; TextDecoder "now supports the full range of text encodings defined by the WHATWG Encoding Standard" since 2022-02-25; URL.canParse since 2023-04-10, which requires the `url_standard` parser (default for compatibility_date 2022-10-31 or later); `nodejs_compat` is default from 2026-08-04. Only quirk: legacy-encoding streaming bugs (workerd #6193, Feb 2026, closed). (https://developers.cloudflare.com/workers/platform/changelog/historical-changelog/; https://developers.cloudflare.com/workers/platform/changelog/; https://developers.cloudflare.com/workers/configuration/compatibility-flags/)
- Guard for all runtimes: `try { new TextDecoder(label) } catch { /* fall back to utf-8 */ }`.
- cheerio 1.2.0 (2026-07-17; node >=20.18.1; 19.8M downloads/week): 11 direct deps including undici ^7.19 and parse5; a clean `npm install cheerio` produced 21 packages and about 8.7 MB on disk (cheerio's own unpacked size 1,011,246 bytes); it ships `import`/`browser`/`require` conditions and a `./slim` entry; README: "Cheerio works in both browser and server environments." esbuild 0.28.2 with Wrangler's conditions (`["workerd", "worker", "browser"]`, from wrangler's bundle.ts) chose `dist/browser` and dropped undici, giving a 621 KB unminified ESM bundle; running it inside workerd was not tested: UNVERIFIED. (npm; local install 2026-09-25; https://raw.githubusercontent.com/cloudflare/workers-sdk/main/packages/wrangler/src/deployment-bundle/bundle.ts)
- article-title 5.0.0 (2025-09-09; 310 downloads/week; ESM, node >=20): its only dependency is cheerio (22 packages, 8.9 MB installed); it reads `<title>` (cut at | - / bullet or em dash) plus 17 heading selectors, and does not read og:title (source read 2026-09-25).
- Zero-dependency alternatives on npm (downloads for the week to 2026-09-21): none is both maintained and zero-dep. get-title 1.1.2 (2022, 8/week; iconv-lite, parse-head, yargs); fetch-meta-tags 1.1.0 (2025-05, 484/week; node-html-parser, which needs entities and css-select); html-metadata-parser 2.0.4 (2022, 1.5k/week; axios, node-html-parser); metascraper 5.58.1 and metascraper-title 5.56.2 (2026-09/08, 107k and 67k/week; cheerio plus helpers); extractus/article-extractor 9.0.1 (2026-08-20, 19k/week; mozilla/readability, linkedom); url-metadata 6.2.0 (2026-09-25, 18k/week; cheerio, node-fetch); html-title was unpublished in 2019. The one useful zero-dep building block is entities 8.1.0 (2026-09-07, 0 deps, 218M downloads/week, node >=20.19, 330 KB unpacked) for entity decoding. Recommendation: write the extractor (regex over `<title>` and `<meta property="og:title">`, decode entities, take the charset from Content-Type or a meta tag and decode with TextDecoder, utf-8 fallback).

## 6. Lint and format

- xo 5.0.1 (2026-09-18; majors 5.0.0 on 09-16, 4.0.0 on 07-06, 3.0.0 on 06-16; 119k downloads/week). ESM-only, node >=22, ESLint flat config on eslint ^10.8.0. Config file `xo.config.js` or `xo.config.ts` (a `FlatXoConfig` array of `{files, rules, ...}`) or the package.json "xo" key. TypeScript works out of the box (.ts/.mts/.cts/.tsx through eslint-config-xo, no tsconfig needed). Prettier ^3.9.6 is a dependency: `prettier: true` formats through Prettier as an ESLint rule, `'compat'` only silences conflicting rules; `space`, `semicolon` and `prettier` are global-only since 5.0; 5.x also lints package.json and enforces `.js`-for-`.ts` import extensions. Editor integration: `eslint.config.js` containing `export {default} from 'xo/eslint-adapter'`.
